# Design

## Context

- `y2k-patch-app.js`: `FORM_HTML` (360x200 window) and `INSTALLED_HTML` (one sentence, `#y2k-installed`); `_apply()` stores `y2k-patch-applied`, swaps the content and calls `_showOverlay()`, which appends `#y2k-overlay` to `#screen`, runs a 2-second progress bar and then shows `#y2k-overlay-message` with an OK button (`#y2k-overlay-ok`). `_markInstalled()` swaps the content when the server already finished the team.
- `timer.js` `beginFinale()` waits (MutationObserver) until `#y2k-overlay` is gone before showing the finale panel.
- Reference image supplied by the user: a window titled `Y2K Emergency Patch` (we keep the window title `Y2K Patch`), globe at the left, big pixel title, a checklist panel and a fireworks panel, a progress bar at 100%, a yellow banner and a Finish button.

## Decisions

1. **One success view.** A `SUCCESS_HTML` template used by both `_apply()` and `_markInstalled()` and at launch when `isApplied()`. Its root keeps `id="y2k-installed"` so existing checks still find it. Layout (CSS grid/flex inside the window content, `box-sizing: border-box`):
   - header row: `<img class="y2k-globe">` (left) + a column with `<h1>Installation complete</h1>` and four lines (`Code accepted.`, `Critical failure avoided.`, `System date stabilized.`, `All operations restored.`);
   - a bevelled panel (same inset shadows as `.y2k-status`/overlay panel) with a two-column body: left a list of four rows, each a green pixel check box and text (`Millennium crisis avoided`, `System files patched`, `Network functions restored`, `Global systems online`); right the caption `31/12/1999 - 23:59` above the fireworks image;
   - a segmented blue progress bar fixed at 100% (reuse the `os-gui` `.progress-indicator` pieces if they render segments, otherwise a repeating-linear-gradient) with `100%` at its right;
   - a banner: yellow background, dark blue bold text `WELCOME TO 2000`, sparkles at both ends, bevelled border;
   - a centered `Finish` button (`id="y2k-finish"`) that calls `this.win.close()`.
   The date uses a plain hyphen to avoid font gaps, and the ASCII text above is the final text (English, as in the image).
2. **Window size.** On success (`_apply`, `_markInstalled`, launch when applied) the window is resized in place to about 640x520 (outer). Discovery confirmed the API: `public/os-gui/$Window.js` exposes `$w.setDimensions({ innerWidth, innerHeight, outerWidth, outerHeight })` (line ~394) which can be called any time, and `$w.center()` (line ~1640) which centers on `#screen` and calls `applyBounds()` (clamps into the desktop). So: `win.setDimensions({ outerWidth, outerHeight })` then `win.center()`, with the target clamped to `#desktop-area` minus a margin before the call; it is clamped to the visible desktop (`#desktop-area` size minus a margin) so it fits on short screens, like the existing "Short screen" requirement. The code form stays at 360x200. The first implementation step is to confirm the resize API and record it in the change.
3. **Install overlay.** Keep `#y2k-overlay` and the 2-second bar. Text becomes larger: `#y2k-overlay-progress` at about 18px (about 1.5x the current 11-12px text) in a wider panel (about 480px). Remove `#y2k-overlay-message` and `#y2k-overlay-ok` from the overlay and the code that shows them: at the end of `INSTALL_MS` the overlay is removed by `_removeOverlay()`. `_installing`/`_onClose` behavior is unchanged, so closing the window mid-install still clears the timer and overlay.
4. **Code accepted line, no code.** The template has no field for the typed code, and nothing about the code is kept after submission.
5. **Assets.** `assets/globe.svg` (24x24 pixel grid scaled to about 128px: blue ocean, green and white continents, a thin golden ring and sparkles) and `assets/fireworks.svg` (about 96x56 grid: night-purple gradient, three bursts yellow/magenta/cyan, a black city skyline with lit windows). Authored as `<rect>` pixels (generated by a one-off script, committed as plain SVG), displayed with `image-rendering: pixelated` and imported with Vite `?url`. The user reviews a screenshot against the reference image.
6. **Font.** Discovery confirmed `Fixedsys Excelsior` is registered via `@font-face` in `src/shared/styles/main.css` (family "Fixedsys Excelsior", `Fixedsys Excelsior.ttf`); `"IBM BIOS"` (`Web437_IBM_VGA_8x14.woff`) is also registered there as a fallback option. Use `Fixedsys Excelsior` only inside this view; body text 14-16px, title about 32px bold.
7. **Finale interplay.** `beginFinale` starts when the overlay is gone, now 2 seconds after the code is accepted. The finale panel and the new window must both be readable; if the finale panel covers the window, the window keeps focus/z-order above it or the finale layout is checked in the screenshot. No change to `timer.js` is planned; if one is needed it is reported before being made.
8. **Tests.** Update `e2e/y2k_patch.spec.js` and `e2e/improving_ct_october.spec.js`: replace assertions on `#y2k-overlay-message`/`#y2k-overlay-ok` with: the overlay shows the install text and disappears by itself within a few seconds; the window then shows `Installation complete`, `Code accepted.`, the four checklist items, `31/12/1999 - 23:59`, `100%`, `WELCOME TO 2000` and `Finish`; the typed code appears nowhere in the window text; `Finish` closes the window; reopening in the same tab shows the same screen without the form; the window size is larger than the form's and fits the viewport; the 360x200 form and wrong-code behavior are unchanged.

## Risks

- Window resize API limits (decision 2).
- Finale timing (decision 7).
- Pixel-art quality: one visual review round with the user may be needed.

## Open Questions

- "Increase the size of those texts" is read as the install overlay text and the new screen text. If the user meant only one of them, adjust in review.
